## 1. 业务背景与目标

### 1.1 业务背景
在数字商业与内容电商爆发的时代，中小创业者、独立开发者和产品经理在寻找创业方向时，面临巨大的信息噪音与需求失真问题。传统的市场调研周期长、成本高，而海量社交媒体（如抖音、TikTok 等）的真实用户评论中沉淀了最原始、最强烈的痛点与需求吐槽。
为了降低从“用户吐槽”到“商业变现”的决策成本，打造一款集“社区评论挖掘、痛点线索提炼与商业方案构思”于一体的智能商机雷达——**商机发现助手 (Oppty Discovery Assistant)**。

### 1.2 应用定位与品牌
- **应用中文名**：商机发现助手
- **应用英文名**：Oppty Discovery Assistant
- **Slogan**：
  - 中文：痛点一键透视，商机即刻成型。
  - 英文：From pain point to profit in seconds.
- **一句话介绍**：一款集“社区评论挖掘、痛点线索提炼与商业方案构思”于一体的智能商机雷达。
- **品牌清理与合规**：彻底清除原工作空间及界面中所有第三方品牌标识及相关名称（如 SeekMoney、SeekMoney-ai 等）。

### 1.3 核心目标
1. **前后端分离与全栈重构**：前端使用 React (TypeScript + 现代设计规范)，后端使用 Go (Gin + GORM)，支持移动端与 PC 端自适应响应式布局。
2. **极简无感认证**：集成 Supabase Auth 邮箱验证码登录机制，实现“登录即注册”，大幅降低用户使用门槛。
3. **闭环智能商机挖掘流**：提供完整链路：选择数据源 → 输入关键词 → 深度爬取配置（视频数 5~20，每视频评论数 10~100） → 自动成本预估 → 异步并发分析（聚类与大模型分析） → 全屏报告沉淀与历史回溯。
4. **技术解耦与资产复用**：集中统一管理提示词（Prompt）、技术组件（Supabase、MinIO、PostgreSQL、TikHub/Qwen LLM）配置，支持灵活迁移与独立部署。

### 1.4 项目范围
- **In-Scope（包含范围）**：
  - **登录与用户管理**：邮箱验证码无感注册/登录，Supabase 认证与用户会话保持，首次登录自动建档。
  - **商机发现工作台**：自适应多端表单，数据源切换（TikTok/抖音），关键词多标签输入，评论爬取开关，视频数（5~20）与评论数（10~100）动态滑块，实时预估成本公式计算。
  - **异步分析与状态感知**：分步进度状态展示（初始化 $\rightarrow$ 数据抓取 $\rightarrow$ 语义聚类 $\rightarrow$ 大模型深度分析 $\rightarrow$ 生成报告），支持任务轮询与重试。
  - **商机深度分析报告**：痛点透视、付费意愿、产品概念、痛点深度、竞品格局、MVP 执行方案、全屏专注查看模式、Markdown/HTML 报告存储与浏览。
  - **商机历史记录中心**：商机历史报告列表查询、详情回溯、时间线展示、删除管理。
  - **配置与提示词中心化**：Go 后端配置文件统一抽取组件地址、密钥与端点；提示词抽取到独立模块集中管理。
  - **双端自适应与现代 UI**：严格遵循 hallmark / ui-skills-root 设计规范，消除 AI 模板感（AI-slop），打造沉浸、专业、高质感的视觉体验。
- **Out-of-Scope（本次暂不涉及）**：
  - 付费订阅与在线支付网关接入（本次仅展示预估消耗成本计算）。
  - 第三方 OAuth（微信扫码/Google 等，本期聚焦邮箱无感登录）。

## 4. 核心业务用例描述 (Use Cases)

### 用例 1：邮箱验证码无感注册与登录 (FEAT-AUTH-01)
- **主执行人**：所有用户
- **前置条件**：用户已打开应用，尚未建立有效认证会话。
- **基本操作流（Happy Path）**：
  1. 用户在登录界面输入有效邮箱地址（如 `user@example.com`）；
  2. 点击“获取验证码”，系统通过 Supabase Auth 服务向该邮箱投递 6 位数字验证码；
  3. 前端启动 60 秒倒计时防重复点击，提示“验证码已发送至您的邮箱”；
  4. 用户输入收到的验证码并点击“验证并登录”；
  5. 后端/前端通过 Supabase 完成凭证校验：
     - 若该邮箱为首次登录：系统自动创建用户账号档案，记录注册时间并初始化配额；
     - 若该邮箱已存在：直接加载该用户历史数据并签发有效会话（Access Token）；
  6. 页面平滑过渡跳转至“商机发现控制台”。
- **异常流与分支流**：
  - 邮箱格式错误：前端即时红字提示“请输入合法的邮箱格式”，阻止发送；
  - 验证码错误或过期：后端返回错误码，前端提示“验证码错误或已失效，请重新获取”；
  - 邮件发送频次超限：提示“发送过于频繁，请稍后再试”。
- **后置条件**：本地存储安全会话凭证，全局用户状态被激活。

### 用例 2：商机发现与成本预估配置 (FEAT-OPPTY-01)
- **主执行人**：已登录用户
- **前置条件**：用户处于商机发现工作台。
- **基本操作流（Happy Path）**：
  1. 用户选择数据来源（支持 TikTok、抖音等数据源）；
  2. 用户在关键词输入框中输入 1~5 个目标行业或产品关键词；
  3. 用户开启【爬取评论】开关（默认开启以提炼深度痛点）；
  4. 用户拖动或输入参数：
     - 视频数量：区间限制为 5 ~ 20 个（默认 10）；
     - 每视频评论数：区间限制为 10 ~ 100 条（默认 20）；
  5. 界面根据设定参数自动实时计算并呈现预估消耗成本：
     $$\text{成本预估} = \left(\frac{\text{maxVideos}}{20} \times 0.01\right) + \left(\text{enableComments} ? \text{maxVideos} \times \frac{\text{maxCommentsPerVideo}}{20} \times 0.01 : 0\right) \text{ 元}$$
  6. 用户确认无误，点击【开始智能分析】按钮；
  7. 系统校验参数合法性，提交后端创建异步挖掘任务，返回任务唯一标识 `jobId`；
  8. 界面进入动态可视化进度加载态。
- **异常流与分支流**：
  - 关键词为空或超过字符上限：表单标红并震动提醒“请输入至少 1 个关键词”；
  - 视频数或评论数超出限制范围：输入框自动校正至边界合法值。

### 用例 3：异步任务状态感知与结果呈现 (FEAT-OPPTY-02)
- **主执行人**：已登录用户
- **基本操作流（Happy Path）**：
  1. 前端基于 `jobId` 自动开启轮询或流式订阅；
  2. 页面进度卡片动态展示执行阶段与实时文案：
     - `crawling`：数据采集（正在抓取社交媒体视频与评论）；
     - `clustering`：语义聚类（正在对高频吐槽进行语义密度分析）；
     - `analyzing`：商业洞察（LLM 正在提炼一句话痛点、付费意愿及 MVP 方案）；
  3. 任务执行成功后，前端即刻渲染多维商机分析矩阵卡片与聚类信号统计。
- **异常流与分支流**：
  - 任务执行失败（三方 API 波动或配额不足）：展示清晰中文失败原因，提供“重新发起”操作。

### 用例 4：商机报告全屏查看模式 (FEAT-OPPTY-03)
- **主执行人**：已登录用户
- **基本操作流（Happy Path）**：
  1. 用户点击分析报告右上角“全屏查看”图标或展开按钮；
  2. 界面进入沉浸式全屏浏览模式，隐藏无关边栏与输入区；
  3. 报告提供结构化标签页或分块导航：
     - 痛点深度（表面痛点、底层根本原因、触发场景、情绪烈度）；
     - 商业格局（竞品缺陷、未被满足的需求、差异化市场切入点）；
     - MVP 落地路线（核心功能、验证假设、首批种子用户渠道、开发时间与成本预估）；
     - 真实声量佐证（代表性用户原声文本）；
  4. 支持一键导出/保存，支持 ESC 键或点击退出按钮平滑返回常规视图。

### 用例 5：商机历史归档与回溯 (FEAT-HIST-01)
- **主执行人**：已登录用户
- **基本操作流（Happy Path）**：
  1. 用户点击顶部导航“商机历史”；
  2. 系统按创建时间倒序呈现当前用户的历史分析记录（展示分析关键词、数据源、痛点摘要、生成时间、信号量）；
  3. 用户点击任意历史卡片，即可快速调取该份商机报告完整内容并进入查看或全屏模式；
  4. 支持按关键词快速搜索历史，支持单条历史的删除归档。

## 5. 非功能性需求 (NFR)

### 5.1 响应性能与自适应体验
- **自适应响应式布局**：完美兼容 PC 宽屏（1920x1080、1440x900）、平板与移动端（iPhone/Android 竖屏 375px+），断点平滑缩放。
- **渲染性能**：首屏加载时间 $\le 1.5s$，卡片展开与全屏切换过渡动画平滑在 60fps。
- **后端接口性能**：Go 后端路由处理及数据库读写 P95 $\le 80ms$（除依赖三方爬虫与大模型分析时间外）。

### 5.2 安全与稳定性
- **会话鉴权**：使用 Supabase 颁发的安全 JWT Bearer 令牌，前端请求拦截器统一注入，后端严格校验。
- **数据隔离**：所有用户生成的商机报告和历史任务基于 `user_id` 强隔离，严禁越权访问。
- **配置与密钥防护**：服务端数据库密码、MinIO 访问密钥、LLM Key 统一置于配置文件，禁止硬编码及向前端泄漏。

### 5.3 编码与工程规范
- **代码中文标准**：所有打印日志、代码注释、测试用例全部统一使用中文。
- **架构约束**：后端采用 Go 官方标准布局（`cmd/`, `internal/handler`, `internal/service`, `internal/repository`, `internal/model`），严禁在 Handler 层泄露底层 Model；禁止使用 Lombok；字符串与枚举统一注册管理。

### 6.4 v1.0.10 变更决策判定（语义向量化与内存 DBSCAN 聚类引擎）
- **判定类型**：三级决策树之【模块内扩展 (A2)】
- **变更动因与效果评审**：
  1. **破除伪聚类硬编码**：原 Go 后端在 `clusterTexts` 方法中使用奇偶下标取模（`i%2 == 0`）对评论强行二分，未进行任何语义理解，导致混杂无关话题、同一痛点被生硬割裂；
  2. **数据噪音泛滥**：爬取的原始评论包含大量纯数字、纯符号、单字、纯表情及广告，无清洗直接送入大模型，耗费 Token 且严重干扰分析质量；
  3. **增强效果评估（极高价值）**：
     - **语义高内聚**：通过大模型 Embedding 将真实原声映射到高维几何空间，相同痛点（如“续航差/耗电快”、“系统卡顿/掉帧”）距离自然接近；
     - **离群点自动去噪**：DBSCAN 算法天然识别并分离孤立噪声点（Noise Points），无需预先设定聚类簇数 $K$；
     - **代表句智能提炼**：结合簇内中心度和文本质量评分，精准提炼代表性原声；
     - **极轻量零负担**：纯内存算法计算，随任务生命周期结束销毁，零向量数据库运维成本；
     - **内网模型现成可用**：直接复用本地网关（`http://192.168.8.206:3002/v1`）已就绪的阿里通义千问官方 `text-embedding-v4`（1536 维）向量模型。
- **需求规格与关键流程**：
  1. **前置数据清洗器 (`DataCleaner`)**：
     - 规则过滤：过滤长度小于阈值（默认 4 字符）、纯数字、纯标点、无意义表情组合、连续重复字符、高频客套口头禅；
     - 痛点特征加权：识别包含「怎么/如何/不会/难用/卡顿/耗电/多少钱/贵/崩溃/报错」等高价值痛点词汇，赋予更高质量分；
  2. **向量化客户端 (`EmbeddingClient`)**：
     - 请求网关 `/v1/embeddings`，模型默认 `text-embedding-v4`；
     - 支持分批（Batch Size 10~20 条）并发/流式获取向量，兼顾单次 payload 限制与超时控制；
  3. **纯内存 DBSCAN 聚类引擎 (`DBSCANClusterer`)**：
     - 纯 Go 实现余弦距离计算：$\text{dist}(u, v) = 1 - \frac{u \cdot v}{\|u\|_2 \|v\|_2}$；
     - DBSCAN 算法参数：邻域半径 $\varepsilon = 0.35$，最小密度点数 $\text{MinPts} = 3$（当样本总数较小时自适应动态调整）；
     - 输出高密度聚类簇与噪点集合；
  4. **优雅容错降级机制**：
     - 若 Embedding 接口网络超时或异常，自动平滑降级至关键词词频或保底分批策略，保证分析流水线整体 100% 不中断，并输出中文告警日志。
